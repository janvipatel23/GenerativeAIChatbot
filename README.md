# 🏥 Generative AI Medical Chatbot

A **RAG-powered medical chatbot** that answers healthcare questions grounded in your own PDF knowledge base. Upload medical documents, index them into **Pinecone**, and interact through a clean **Flask web interface** — with answers generated by **Llama 3.3 70B** via Groq, backed by semantic similarity search.

---

## ✨ Features

- **Document-Grounded Answers** — All responses are retrieved from your own medical PDFs, not hallucinated from general training data.
- **Semantic Vector Search** — HuggingFace Sentence Transformer embeddings (384-dim) stored in Pinecone enable fast, accurate similarity retrieval.
- **LLM-Powered Responses** — Groq's `llama-3.3-70b-versatile` generates clear, contextual answers based on retrieved document chunks.
- **Flask Web Chat UI** — A purpose-built HTML/CSS chat interface for interactive Q&A directly in the browser.
- **Two-Phase Architecture** — Ingestion and querying are cleanly separated: index your docs once, then query indefinitely.
- **Serverless Vector Store** — Pinecone Serverless on AWS handles embedding storage with zero infrastructure management.
- **Packaged as a Module** — The `src/` helper utilities are installable as a Python package via `setup.py`.

## 🚀 Getting Started

### Prerequisites

- Python 3.11+
- A [Pinecone account](https://www.pinecone.io/) with an API key
- A [Groq API key](https://console.groq.com/)

### 1. Clone the Repository

```bash
git clone https://github.com/janvipatel23/GenerativeAIChatbot.git
cd GenerativeAIChatbot
```

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

This installs all dependencies and also installs the `src/` package in editable mode (`-e .`).

### 3. Configure Environment Variables

Create a `.env` file in the project root:

```env
PINECONE_API_KEY=your_pinecone_api_key_here
GROQ_API_KEY=your_groq_api_key_here
```

### 4. Add Your Medical PDFs

Place your medical PDF documents inside the `data/` directory:

```
data/
├── medical_book.pdf
├── drug_reference.pdf
└── clinical_guidelines.pdf
```

### 5. Build the Pinecone Index (One-Time Setup)

This step loads all PDFs, chunks and embeds them, and upserts into Pinecone:

```bash
python store_index.py
```

This will automatically create a Pinecone Serverless index named **`medical-chatbot`** on AWS `us-east-1` if it doesn't already exist (384 dimensions, cosine metric).

### 6. Launch the Chatbot

```bash
python app.py
```

Open your browser at `http://localhost:8080` and start asking medical questions.

## 🔄 RAG Pipeline Deep Dive

### Indexing Pipeline (`store_index.py`)

```
load_pdf_file("data/")          → PyPDF extracts text from all PDFs
       ↓
filter_to_minimal_docs()        → removes empty/noise documents
       ↓
text_split()                    → LangChain splits into overlapping chunks
       ↓
download_hugging_face_embeddings() → loads Sentence Transformer model
       ↓
PineconeVectorStore.from_documents() → embeds + upserts all chunks
```

### Query Pipeline (`app.py`)

```
User question (POST /get)
       ↓
Embed question → vector
       ↓
Pinecone similarity search (k=3) → top 3 relevant chunks
       ↓
create_stuff_documents_chain → concatenates chunks into context
       ↓
ChatPromptTemplate → system_prompt + context + user question
       ↓
ChatGroq (llama-3.3-70b-versatile) → generates answer
       ↓
response["answer"] returned to chat UI
```

## ⚙️ Configuration Reference

| Parameter | Value | Description |
|---|---|---|
| Pinecone index name | `medical-chatbot` | Name of the vector index |
| Pinecone dimensions | `384` | Matches Sentence Transformer embedding size |
| Pinecone metric | `cosine` | Similarity metric for retrieval |
| Pinecone cloud | `aws` | Cloud provider |
| Pinecone region | `us-east-1` | Serverless region |
| Retriever search type | `similarity` | Vector similarity search |
| Retriever `k` | `3` | Number of chunks retrieved per query |
| LLM model | `llama-3.3-70b-versatile` | Groq model used for generation |
| Flask host | `0.0.0.0` | Accessible on all network interfaces |
| Flask port | `8080` | Application port |
| Flask debug | `True` | Auto-reload in development |
